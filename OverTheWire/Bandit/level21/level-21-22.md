# Bandit Level 21 → Level 22

### 🎯 Objective
A program is running automatically at regular intervals from cron, the time-based job scheduler. Look in /etc/cron.d/ for the configuration and see what command is being executed.

### 🔍 Information & Clues
• **Host:** bandit.labs.overthewire.org
• **Port:** 2220
• **Username:** bandit21
• **Commands to research:** cron, crontab, cat, ls, cd

### 💡 Thought Process & Steps
1. **Connecting:**
I logged into the level using SSH:

```bash
ssh bandit21@bandit.labs.overthewire.org -p 2220
```

2. **Enumeration:**
I navigated to the cron configuration directory to check what background jobs were scheduled:

```bash
cd /etc/cron.d/
```

Inside the directory, I listed the available configuration files:

```bash
ls
```

I identified a file named cronjob_bandit22 and inspected its contents to find what script was running:

```bash
cat cronjob_bandit22
```

Output snippet: * * * * * bandit22 /usr/bin/cronjob_bandit22.sh &> /dev/null

This configuration indicates that every minute (* * * * *), the user bandit22 executes a bash script located at /usr/bin/cronjob_bandit22.sh.
I then read the contents of that background script to understand what it does:

```bash
cat /usr/bin/cronjob_bandit22.sh
```

Output script:

```bash
#!/bin/bash
chmod 644 /tmp/t7O6lds9S0RqQh9aMcz6ShpAoZKF7fgv
cat /etc/bandit_pass/bandit22 > /tmp/t7O6lds9S0RqQh9aMcz6ShpAoZKF7fgv
```

The script reveals that the password for bandit22 (stored in /etc/bandit_pass/bandit22, which our user cannot read directly) is constantly being copied into a publicly readable temporary file located at /tmp/t7O6lds9S0RqQh9aMcz6ShpAoZKF7fgv.

3. **Reading the Flag:**
Since the script modifies permissions (chmod 644) to make the temporary file world-readable, I simply used cat to print out the target file's content and retrieve the password:

```bash
cat /tmp/t7O6lds9S0RqQh9aMcz6ShpAoZKF7fgv
```

### 🔑 Key Features Learned
* cron / cron daemon: A time-based job scheduler in Unix-like operating systems that enables users to schedule jobs (commands or shell scripts) to run automatically at specified intervals, times, or dates.
* crontab configuration sstructure: The format used in /etc/cron.d/ contains time parameters (minute hour day-of-month month day-of-week), followed by the username executing the task, and finally the command/script itself.
* &> /dev/null: A redirection syntax used to silence standard output and standard error simultaneously, sending them to the null device so no logs or terminal outputs are generated by the background job.
